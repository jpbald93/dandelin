# Dandelin spheres in Lean 4

A Lean 4 + Mathlib formalisation of **Dandelin's theorem** for all three conic sections: the inscribed spheres of a cone tangent to a cutting plane, the focal-sum (ellipse) and focal-difference (hyperbola) properties in both directions, the focus–directrix property with eccentricity `e = cos β / cos α` and its converse, non-emptiness, the classification of sections by the angle of the plane, and planes through the apex. Statements are in an arbitrary real inner product space, with explicit finite-dimension hypotheses where they are needed.

**Status:** all statements proved, with no `sorry`. `gate.sh` checks 75 named declarations.

## Main statements

| Lean name | File | Statement |
|---|---|---|
| `Dandelin.dandelin_exists` | `Existence.lean` | exactly two axis-family spheres tangent to the plane; the section is the ellipse `|XF₁|+|XF₂| = const` |
| `Dandelin.dandelin_converse` | `Existence.lean` | every point of the plane with that focal sum lies on the cone |
| `Dandelin.dandelin_hyperbola` | `Hyperbola.lean` | two-nappe cone: constant focal difference on both branches |
| `Dandelin.directrix_ellipse` | `Directrix.lean` | focus–directrix property with `e < 1` |
| `Dandelin.directrix_parabola` | `Directrix.lean` | parabola: one sphere, `e = 1` |
| `Dandelin.directrix_converse` | `Degenerate.lean` | converse of the focus–directrix property |
| `Dandelin.regime_R3` | `Regime.lean` | in ℝ³: ellipse / parabola / hyperbola according to `sin α` vs `|⟪u,n⟫|`; sections are non-empty |
| `Dandelin.apex_section_R3` | `Degenerate.lean` | plane through the apex: a point, one line, or two lines |

The one-nappe converse for the hyperbola is false; `Degenerate.lean` contains a Lean counterexample.

## Verification

`./gate.sh` builds the library and generates its own `#print axioms` queries for the 75 named
declarations (every Lean name cited in the accompanying paper, plus those queried during
development). The queries are generated by the gate itself, not read from a file in the repository.

The gate fails if any of the following is true:
- a source file contains `sorry`, `admit`, `native_decide`, `axiom`, `#eval`, `run_cmd`, `set_option`, `macro`/`elab`/`syntax`/`notation`, or `import Lean`;
- the build fails;
- a named declaration is missing, or has an extra report;
- a named declaration depends on anything other than `propext`, `Classical.choice` and `Quot.sound`.

Output: `PASS (75 declarations, standard axioms only)`.

`tests/tamper.sh` plants six kinds of fake proof in scratch copies and checks that the gate
rejects each one (a rejection must exit nonzero and print the expected `FAIL` message): a `sorry`; an axiom split across two lines; an `#eval` printing a fake axiom
report; a custom macro; a weakened statement (apex section = {V} with the strict inequality weakened to ≤: false at equality (a line).); and a genuine extra
axiom with a long name, so that the report wraps over several lines.

`code/` contains independent numerical checks (Python, exact or high-precision arithmetic) of the
identities and of the hypotheses' necessity. `scratch/` contains the `#print axioms` driver files used during development; their recorded
outputs, cited in the paper, are the `*.out` files there and the log files at the repository root.

## Build

```sh
curl https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh -sSf | sh   # if Lean is not installed
lake exe cache get
lake build
./gate.sh
bash tests/tamper.sh
```

Toolchain: Lean `v4.33.1`, Mathlib `v4.33.1` (revision pinned in `lake-manifest.json`).

## Note on how this was produced

The formal proofs, checking scripts and documentation were developed with the help of a
large-language-model AI assistant. The author directed the work, checked the formal statements
against their informal counterparts by hand, and is responsible for the result. The Lean kernel
checks every proof.
